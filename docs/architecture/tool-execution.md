# Tool execution

Local tools run in the renderer, web tools go through Tauri commands (CORS). The web-search toggle is per chat and persisted.

## Web fetch caps

The page body is streamed against a 2 MB cap (`MAX_HTML_BYTES` in `tauri/src/tools/fetch.rs`); don't revert it to `res.text()`, which buffers the whole response. The fallback `strip_tags` uses `to_ascii_lowercase` rather than `to_lowercase` so byte offsets stay aligned for slicing.

`src/lib/tools.js` exports `TOOLS` + `executeTool(name, args)`. Local tools (e.g. `get_current_time`) run in the renderer; web tools (`web_search`, `web_fetch`) invoke Tauri commands (CORS), implemented in `tauri/src/tools/`.

Web search has a global default in `useSettingsStore` (`webSearchDefault`, **off** by default); the per-pane toggle lives in the chat store (`webSearchEnabled`) and seeds from it. **Each chat remembers its own value**: `ChatPane` keys the toggle by session id (or side-chat id) and keeps it in `chatStore.js`'s `_webSearchByChat` map, hydrated from the `webSearch` field `load_sessions` returns and written through per chat (`set_session_web_search` / `set_side_chat_web_search`), so switching chats restores that chat's toggle and a restart keeps it. The map can't be the pane store alone — the main pane's store is shared across sessions, and a side tab's `ChatPane` unmounts when the panel closes. A chat with no remembered value falls back to its default; `clearMessages` (New Chat) seeds a fresh one from the setting. **A side chat inherits its parent pane's current toggle instead of the global default** — the parent is the `contextStore` SidePanel already passes (the main chat, or the parent side chat for a branch), and the main pane has none so it uses the setting. The toggle decides whether a pane may reach the web, so a question asked of a pane with search on starts on too. `useStreamingChat` filters web tools out of `TOOLS` when the toggle is off. **In Codebase mode the default is off whatever the setting says**: file reads plus web access is the egress pair (a fetched page can order a file read, and a file can leave inside a URL), so `ChatPane` re-derives the toggle when the root set changes, and turning web search back on mid-codebase is a deliberate act (the forced-off is written as that chat's value, so a restart while attached keeps it off). `ChatPane` derives `codebase` exactly as `useStreamingChat` does — the pane's roots, else its session's — because a side chat has no roots of its own and the two must agree or the default silently doesn't apply.
